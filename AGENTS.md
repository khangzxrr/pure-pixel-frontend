# PurePixel frontend

React 18 + Vite 5 SPA for the PurePixel photography marketplace (FPT University capstone). REST + Socket.IO to the backend, Mapbox maps, Ant Design UI, Vietnamese copy.

Auth depends on the branch: `main` and older branches sign in with Keycloak; the `authentik` line replaces it with Authentik OIDC (`oidc-client-ts` behind the same components). Check the code before assuming an auth env variable exists.

## Commands (from the repo root)

- Yarn 1 only (`yarn.lock`, `packageManager`); do not use npm/pnpm.
- `cp example.env .env`, `yarn dev` → http://localhost:3000
- Checks: `yarn lint`, `yarn typecheck` (`tsc --noEmit`), `yarn test` (vitest + jsdom)
- One test: `npx vitest run <path>`; cap workers if a full run flakes (`--maxWorkers=8`)
- Coverage gate: `yarn test:coverage` (90%); `yarn build` must succeed.

## Conventions

- Reuse the test helpers in `src/test/`: `render.tsx`, MSW `server.ts`, auth mock `keycloak.ts`.
- `src/apis/generated/schema.d.ts` is generated by `yarn api:generate` (it reads `../pure-pixel-backend/openapi.json`, generated in the backend repo) and is committed; never hand-edit it.
- The app mixes legacy `.js/.jsx` (kept compiling via `allowJs`) with `.ts/.tsx`; write new code in TypeScript, keep `any` out (lint error), prefix required-but-unused args with `_`.
- The UI is Vietnamese (Ant Design `vi_VN` locale); keep user-facing copy Vietnamese.
- `VITE_*` values are inlined at build time, so each environment needs its own build.

## Auth

- Keycloak branches: `VITE_KEYCLOAK_URL`, `VITE_KEYCLOAK_REALM`, `VITE_KEYCLOAK_CLIENT_ID`; `keycloak-js` + `@react-keycloak/web`, silent SSO via `public/silent-check-sso.html`.
- Authentik branches: `VITE_OIDC_AUTHORITY`, `VITE_OIDC_CLIENT_ID`, `VITE_AUTH_REGISTER_URL`; components keep working through the `AuthentikClient` adapter in `src/services/`.
- Tokens carry roles `customer`, `photographer`, `manager`, `purepixel-admin`; route protection lives in `src/routers/` and `src/authorize/`.

## Deploy

- Pushing to `main` auto-deploys over SSH (`.github/workflows/node.js.yml`): pull, then `yarn install && yarn build`. Do not push WIP to `main`.
- SPA routing relies on `netlify.toml` / `public/_redirects`; the Docker image builds with nginx and takes the `VITE_*` values as build args.
